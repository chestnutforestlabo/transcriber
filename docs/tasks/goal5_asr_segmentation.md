# Goal 5: channel_mode の ASR 精度改善(VAD 区間単位 ASR + Whisper チューニング)

## 背景(実測)

調査1(銀座歩行、2ch)での A/B 結果:
- `openai`(whisper large-v3): セグメント粒度は良いが、認識漏れ・誤認識が目立つ
- `qwen`(Qwen3-ASR-1.7B): **認識精度が明確に最良**。ただし内部タイムスタンプを返さないため、チャンネル全体(〜270秒)が1セグメントになる
- `kotoba`: 今回の音源では乱れが多い。同じくタイムスタンプなし

コーディングには発話単位のタイムスタンプが必須なので、qwen の精度を活かすには時刻付与の構造改修が必要。

## 実装してほしいこと

### 1. VAD 区間単位の ASR(主目的)

- channel_mode では既に Silero VAD で各チャンネルの発話区間を検出している。**タイムスタンプを返さない ASR バックエンド(qwen / kotoba)の場合、この VAD 発話区間ごとに個別に ASR を実行**し、出力セグメントの Segment(start, end) = VAD 区間とする。
- 近接する VAD 区間(間隔 0.3 秒未満程度)は1回の ASR 呼び出しにまとめてよい(境界は維持)。30 秒を超える連続発話は既存の分割ロジックで分ける。
- 各区間の前後に 0.2 秒程度のパディングを付けて切り出す(語頭・語尾の欠け防止。タイムスタンプは元の VAD 境界を報告)。
- `openai`(whisper)は word timestamps を持つため現状の方式を維持する。
- 空文字・ハルシネーション対策: ASR 結果が空、または「ご視聴ありがとうございました」等の定型ハルシネーションのみの区間は出力しない(定型パターンは定数リストに)。

### 2. Whisper の精度オプション(副目的)

- `--asr_beam_size`(デフォルト 5)を追加し、openai whisper の transcribe に beam_size として渡す(現状は greedy)。
- `--asr_initial_prompt`(デフォルトなし)を追加し、whisper の initial_prompt に渡す(固有名詞・ドメイン語彙のヒント用)。README に使用例(例: "銀座、ルイ・ヴィトン、シャネル、ピンマイク、文字起こし")を記載。

## 制約・受け入れ基準

- 通常モード(非 channel_mode)の挙動は変えない。
- pytest: モック ASR で (a) qwen/kotoba 相当のバックエンドが VAD 区間ごとに呼ばれ、Segment が VAD 境界と一致すること (b) パディングが切り出しにのみ適用されること (c) ハルシネーション定型の除外、を検証。既存テストは全部通ること。
