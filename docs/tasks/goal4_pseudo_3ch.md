# Goal 4: 擬似3チャンネル(Mac 2ch + iPhone 1ch)モードの追加

## 背景とユースケース

3人の会話を「1人1マイク」で録音するための低予算構成。DJI Mic Mini 2 は 2TX までなので、3人目は iPhone + AirPods で別デバイス録音し、後処理で統合して擬似的に 3ch にする。

- 話者A: DJI TX1 → RX(Mac 接続)→ Lch
- 話者B: DJI TX2 → RX(Mac 接続)→ Rch
- 話者C: AirPods マイク → iPhone のボイスメモ(モノラル m4a)
- Mac と iPhone は**別々に録音開始**する(同時である必要はない)。開始直後と終了直前に、全マイクに聞こえるように**手を1回叩く**(クラップ)。これが時刻合わせのアンカーになる

Goal 2 の `--channel_mode`(2ch、Silero VAD + RMS 比較によるクロストーク除去)を N チャンネルに一般化する形で実装する。

## 実装してほしいこと

### 1. 補助チャンネル入力の追加

- `transcribe.py` に `--aux_audio <path>` を追加(複数指定可、`nargs="+"`)。`--channel_mode` と併用した場合のみ有効。
- メイン音声(`--audio_dir` 内の 2ch WAV)= 基準タイムライン。aux はモノラル扱い(多チャンネルなら ch0 を使用)。
- aux が WAV 以外(m4a 等、ボイスメモの出力)の場合は ffmpeg で WAV に変換してから読む(コンテナ内に ffmpeg あり)。
- 話者ラベル: Lch=SPEAKER_00、Rch=SPEAKER_01、aux1=SPEAKER_02、aux2=SPEAKER_03…

### 2. 自動アライメント(クラップ相互相関)

- 別デバイス録音のため、開始オフセットとクロックドリフトを推定して aux をメインのタイムラインに合わせる。
- 方法: 波形そのものではなく**オンセット強度エンベロープ**(librosa の onset envelope 等。デバイス・コーデックが違っても頑健)の相互相関でオフセットを求める。
  - 録音先頭側の窓(デフォルト先頭 120 秒)で開始オフセットを推定
  - 録音末尾側の窓でも推定し、2点からドリフト(1次)を補正する。末尾で相関が取れない場合はドリフト補正なしで警告を出す
- 推定したオフセット・ドリフト・相関のピーク信頼度を stdout と出力 JSON の meta に記録する。信頼度が低い場合(ピークが不明瞭)ははっきり警告し、`--aux_offset <sec>` による手動指定でのオーバーライドも可能にする。
- リサンプル(16kHz)と重複区間へのトリムを行い、以降は既存の channel_mode と同じ土俵に載せる。

### 3. クロストーク除去の N チャンネル一般化

- 現在のペア比較(L vs R)を一般化する: 各チャンネルで VAD → 発話区間ごとに全チャンネルの短時間 RMS を比較し、最大のチャンネルに帰属。最大チャンネルとの差が閾値(既存の `--channel_crosstalk_threshold_db`、デフォルト -6dB)以内のチャンネルは同時発話として両方残す。
- **重要: デバイス間でマイク感度・ゲインが違う**(DJI と AirPods)。RMS 比較の前に、チャンネルごとの発話レベル正規化(そのチャンネルの VAD 検出区間の中央値 RMS で正規化する等)を入れること。正規化方法は定数・コメントで根拠を明記。
- 既存の 2ch 動作(aux なし)は結果が変わらないこと(後方互換)。既存テストがそのまま通ること。

### 4. Mac 用録音スクリプト `scripts/record_mac_dji.sh`

- macOS 上で実行する前提のスクリプト(コンテナ内ではない)。
- `ffmpeg -f avfoundation` で DJI RX(USB オーディオデバイス)から 2ch WAV を録音する。
  - 引数なし実行でデバイス一覧(`-list_devices true`)を表示し、デバイス名/番号を指定して録音開始、Ctrl-C で停止。
  - 出力ファイル名はタイムスタンプ付き(例: `rec_20260801_143000.wav`)。48kHz/16bit/2ch。
- macOS に ffmpeg がない場合の案内(`brew install ffmpeg`)をスクリプト内エラーメッセージで出す。

### 5. ドキュメント(README に擬似3chセクション追加、日本語)

- 機材構成図、録音プロトコル:
  1. Mac で `record_mac_dji.sh` 開始、iPhone でボイスメモ開始(順不同、厳密に同時でなくてよい)
  2. 全マイクに聞こえる位置で手を1回叩く
  3. 会話
  4. 終了前にもう1回叩き、両方停止
  5. iPhone の m4a を AirDrop 等で Mac へ、Mac の wav と一緒に転送
- 実行例:
  ```bash
  uv run src/backend/transcribe.py \
    --audio_dir audios/num_speakers_3 \
    --asr_model_name openai \
    --channel_mode \
    --aux_audio aux/speakerC.m4a
  ```
- 注意書き: AirPods は Bluetooth HFP のため帯域が狭い(実質16kHz)が、Whisper は入力を16kHzに落とすため影響は限定的であること。iOS ショートカットでボイスメモの開始/停止を自動化できること。
- ボイスメモの m4a はモノラルである前提。ステレオだった場合は ch0 を使う旨をログに出す。

## 制約・受け入れ基準

- 既存の 2ch channel_mode・通常モードの挙動を変えない(既存テスト全パス)。
- pytest 追加:
  - 合成音声でのアライメント: 既知オフセット(例 1.7 秒)+人工クラップ(短いバースト)を持つメイン/aux ペアを numpy で生成し、推定オフセットが ±30ms 以内であること。ドリフト補正(例 +50ppm)のケースも1つ。
  - 3ch ゲーティング: 各チャンネル固有の発話区間+相互の漏れ込み(-12dB)を合成し、正しいチャンネルに帰属・漏れ込み除外・同時発話の併存を検証(ASR はモック)。
  - ゲイン差正規化: aux のゲインをメインの半分にしても帰属が変わらないこと。
- 依存追加が必要なら pyproject.toml を更新(scipy は librosa 経由で既にあるはず。新規追加は最小限に)。
- モデルダウンロードが必要な統合テストは書かない。
- コミットはしないこと。最後に変更ファイル一覧と実現できなかった項目(あれば理由付き)を報告すること。
